# 每日复盘功能说明

> 更新时间：2026-10-12
> 状态：当前工作区实现说明（包含尚未发布的更新，见 [更新日志](../CHANGELOG.md)）。本文以当前前端页面、Tauri 命令和 SQLite 数据结构为准；未实现的后续能力不在本文承诺范围内。

## 1. 功能定位

每日复盘以当天**已排程行动**和各时间段填写的执行记录为依据，帮助用户回顾执行结果、整理复盘思考，并在处理事件篮后进入次日计划。

它与相邻功能的分工如下：

| 功能 | 记录内容 | 作用 |
| --- | --- | --- |
| 今日事 / 时间段复盘 | 某一时间段的实际备注、是否达预期、是否专注、主要偏差原因 | 留下可核对的执行事实 |
| 每日复盘 | 当天完成度、四象限安排、执行轨迹、系统归纳的整体状态及用户思考 | 汇总当天，并引导准备明日 |
| 明日计划建议 | 近 7 天重复出现的时间段偏差原因 | 在安排次日计划时提供规则提示 |

每日复盘不会自动调整已有行动、改期、拆分任务或清空事件篮；这些操作仍由用户在相应页面完成。进入次日计划时仅生成匹配规则的重复行动并尝试填入空白时间段，不覆盖已有安排。

## 2. 进入条件与日期范围

### 2.1 入口

用户在「今日事」点击进入每日复盘。当天最后一个已绑定行动的时间段完成复盘后，系统会弹出一次确认框，邀请用户进入今日复盘；选择“稍后再说”不会阻断后续使用。

### 2.2 前置校验

所选日期须有已排程行动，否则提示“请先安排行动后再进行今日复盘”。进入前会检查所选日期所有**已绑定行动**的时间段。每段均须同时满足：

- 已填写非空的实际复盘备注；
- 已选择是否达到预期；
- 已选择是否保持专注。

存在未复盘时间段时，页面会提示剩余数量并停留在「今日事」；即使通过路由直接访问每日复盘页，页面也会返回对应日期的「今日事」。未绑定行动的空白时间段不计入此校验。

### 2.3 日期

每日复盘使用本地日历日期。页面顶部可切换日期，并显示存在行动排程的日期标识；可以补录过去日期。进入明日计划时，系统会将当前复盘日期顺延一天。

## 3. 页面内容与交互

页面由三个步骤组成。

### 3.1 今天过得怎么样？

**行动完成度**展示当天已排程行动的去重统计：计划行动数、涉及事件数、已完成数、未完成数和完成度。

**行动安排优先级**按行动的 `importance` / `urgency` 展示四象限：

- 重要且紧急（`11`）
- 重要不紧急（`10`）
- 不重要且紧急（`01`）
- 不重要不紧急（`00`）

每个象限显示行动数、该象限计划时长占全部已排程时长的比例、计划分钟数和已完成行动数。未安排任何行动时，所有统计均显示为 0，不生成模拟数据。

**今日执行轨迹**按时间顺序显示当天所有时间段，包括时间范围、绑定行动、是否达预期、是否专注、主要偏差原因和实际复盘备注。备注仅为重复行动标题或“完成 + 行动标题”时，会被识别为无有效补充说明。

**时间段复盘汇总**统计已填写有效备注的行动时间段、未达预期段数、未专注段数，并按主要偏差原因聚合对应的时间段。

### 3.2 今日复盘思考

整体状态不由用户手动选择，而是由时间段复盘自动推导：

| 状态 | 判定规则 |
| --- | --- |
| 顺利 | 不满足以下两种偏差条件，或当天没有时间段 |
| 有偏差 | 未达预期的时间段占全部时间段超过 30% |
| 比较混乱 | 未保持专注的时间段占全部时间段超过 30%；同时满足两类条件时优先显示此状态 |

页面会依据整体状态、完成度和四象限数据提供复盘事实与问题提示。用户可在 Markdown 编辑器中自由记录复盘思考；系统不会把时间段备注自动拼接或写入该文本。

草稿在状态或思考内容变化后约 700ms 自动保存。状态浮层显示“正在自动保存…”；成功后显示“已自动保存 HH:mm”，约 3 秒后隐藏，不再逐次弹出成功提示。失败显示“自动保存失败”及错误消息，原有编辑内容保留在页面中。重新打开同一天时会恢复已保存的思考文本；整体状态会根据当前时间段复盘记录重新计算。

### 3.3 明天会更好

该区域以两步引导收尾：

1. 清空事件篮中的待处理事项。存在待处理事件时可跳转「事件篮」处理；没有待处理事件时显示“已清空”。
2. 事件篮清空后，才可点击“去安排明日计划”。按钮显示加载状态，先初始化次日重复行动，成功后才跳转至次日「今日事」并请求、展示适用的复盘建议；初始化失败则提示错误且不跳转。每个空间、每个日期只初始化一次，其余行动安排、青蛙选择和计划保存仍由用户完成。具体排程及冲突规则见 [产品说明](./人生规划软件%20V1.0.md)中的“重复行动与习惯”。

页面右下角始终提供“返回今日事”；滚动超过一定距离后，会同时提供“回到顶部”。

## 4. 数据来源与统计口径

| 展示项 | 数据来源 | 当前口径 |
| --- | --- | --- |
| 已排程行动、完成数、未完成数 | `daily_schedule_slots` 关联未删除的 `actions` | 只统计 `action_id` 非空的时间段；按行动 ID 去重；`actions.status = 1` 为已完成 |
| 涉及事件数 | 同上 | 已排程行动关联的非空 `event_id` 去重计数 |
| 四象限 | `actions.importance`、`actions.urgency` | 按 `importance + urgency` 分组；四类均在前端补齐显示 |
| 计划分钟 | `daily_schedule_slots.start_time/end_time` | 同一行动安排在多个时间段时，各时间段时长都会累计；完成数仍按行动去重 |
| 执行轨迹 | `daily_schedule_slots` | 按当前日期加载所有时间段，展示用户填写的执行字段 |
| 待处理事件篮 | `events` | 前端从事件列表筛选 `status = 0` 的事件 |
| 明日建议 | 最近 7 个已结束日的 `daily_schedule_slots.primary_review_reason` | 同一原因在至少 3 个不同日期出现，且该段未达预期或未专注时触发；`other` 不触发 |

## 5. 偏差原因与明日建议

时间段复盘可选的主要偏差原因如下：

| 原因代码 | 含义 | 建议 |
| --- | --- | --- |
| `plan` | 计划与估时问题 | 减少安排量，为同类任务预留缓冲。 |
| `priority` | 优先级或主动调整 | 明确明日最重要事项，避免临时切换。 |
| `interrupt` | 外部打断 | 预留缓冲时间，集中处理临时事项。 |
| `dependency` | 前置条件受阻 | 提前确认前置条件，并准备替代任务。 |
| `clarity` | 任务不清晰 | 安排前先明确下一步和完成标准。 |
| `energy` | 精力与状态不足 | 将高认知任务安排在精力较好的时段。 |
| `other` | 其他 | 仅用于记录，不生成重复问题建议。 |

建议由本地规则生成，不调用 AI，不上传复盘文本、行动标题或其他数据。建议仅在从每日复盘进入次日计划的该次导航中展示，供用户参考，不会自动修改计划。

## 6. 存储与接口

### 6.1 数据表

`daily_reviews` 以 `(space_id, review_date)` 唯一保存一天一条复盘草稿，当前实际读写字段为：

- `space_id`
- `review_date`
- `overall_status`
- `reflection_text`
- `created_at`
- `updated_at`

表中保留的 `deviation_reasons_json`、`deviation_note` 字段当前未由每日复盘页面读写。数据库当前 schema 版本为 v21，兼容既有本地数据库。重复行动模板新增 `auto_schedule`、`schedule_type`、`schedule_days`、`start_time` 字段；`daily_recurring_initializations` 以 `(space_id, list_date)` 唯一记录初始化，保存触发来源和创建时间，避免启动与复盘重复生成同日实例。旧模板默认不启用自动安排。

### 6.2 Tauri 命令

| 命令 | 用途 |
| --- | --- |
| `get_daily_review(review_date)` | 返回指定日期的复盘草稿与实时统计摘要 |
| `save_daily_review_draft(payload)` | 按日期 upsert 保存整体状态与复盘思考 |
| `get_daily_review_suggestions(plan_date)` | 返回计划日前 7 天达到触发条件的规则建议 |
| `initialize_recurring_actions_for_date(list_date, trigger_source)` | 初始化目标日期日程及重复行动；来源为 `app_start` 或 `daily_review`，同空间同日期不重复执行 |

所有读取和写入均按当前本地空间（`space_id`）隔离。日期参数必须是 `YYYY-MM-DD` 格式。

## 7. 当前边界与后续方向

当前版本不包含以下能力：复盘“完成”状态、未完成行动处置、明日 Top 1、改进实验、历史趋势、周/月复盘、AI 建议和复盘埋点。复盘统计为实时计算，后续行动状态或排程变化可能影响同一日期再次打开时看到的统计结果；复盘思考文本则独立保留。

后续若扩展上述能力，应先同步更新数据模型、事务边界、隐私说明和本文档，避免将规划能力误写为已上线功能。


## 8. 今日专注分布（2026-10-12）

复盘读取所选日期的番茄钟记录，复用 TodayFocus 展示专注分钟数、完成 / 中断次数、专注 / 休息分布及中断原因。统计按本地当日边界、实际结束时间及计划结束时间裁剪，依固定 25 分钟工作、5 分钟休息重建阶段，不计休息，不补算提前结束后的时间。

宽窗口中与执行轨迹等高并排，记录按开始时间正序，溢出时渐隐并提供“展开全部 / 收起”；展开后记录区域可滚动。窄窗口纵向排列。折叠仅影响明细，不改变全天统计。

执行轨迹保留所有非空复盘备注，即使与行动标题相似；空备注显示“未填写复盘备注”。专注记录不替代时间段复盘，也不改变进入复盘的前置校验。

新增命令 get_today_focus(start, end) 按当前空间读取与日期范围重叠的记录；参数为本地日期转换的毫秒时间戳，范围须大于零且不超过 90,000,000 毫秒。get_focus_detail(record_id) 按当前空间读取单条记录。配色见 [界面颜色规范](ui-color-guidelines.md)。
