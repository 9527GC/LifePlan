# 行动优先级编号规范化设计

## 背景

当前系统使用 `importance * 2 + urgency + 1` 计算优先级，导致“重要且紧急”显示为 P4，“不重要且不紧急”显示为 P1，与产品预期的优先级语义相反。

## 目标

统一采用数字越小优先级越高的规则，并修正已有数据：

- P1：重要且紧急
- P2：重要但不紧急
- P3：不重要但紧急
- P4：不重要且不紧急

## 实施范围

1. 修正后端所有新建和更新场景的优先级计算。
2. 将已有项目、行动、周期行动中的优先级按重要程度和紧急程度重新计算。
3. 保持前端按照 P1 到 P4 的顺序排序和展示。
4. 增加自动化检查，覆盖四种重要/紧急组合及历史数据修正逻辑。
5. 更新技术规划中的优先级说明，避免代码和文档不一致。

## 计算规则

使用统一公式：

```text
priority = 4 - (importance * 2 + urgency)
```

其中 `importance` 和 `urgency` 均为 0 或 1。

## 数据修正

已有记录不直接对旧 priority 做简单加减，而是根据当前记录保存的 `importance` 和 `urgency` 重新计算，确保数据与语义一致。修正范围包括项目、行动和周期行动。

项目下行动已有项目级重要/紧急值时，运行时继续使用项目级值；数据库修正仍分别按记录自身字段计算，避免破坏无项目行动和周期行动的数据。

## 验收标准

- 截图中的“重要 + 紧急”行动显示为 P1。
- 四种组合分别显示 P1、P2、P3、P4。
- 新建、编辑项目、编辑行动、编辑周期行动均遵循同一规则。
- 已有数据重新启动应用后不再出现“重要且紧急显示 P4”。
- 今日事列表仍按 P1、P2、P3、P4 排序。
