# 事件篮项目 Tab 合并设计

## 目标

将事件篮与项目的可见入口合并：事件篮继续承载事件收集和处理流程，并新增“已转项目”Tab 展示项目卡片；左侧导航移除独立的“项目”入口。事件状态筛选从下拉框改为平铺 Tab，其中“待处理”只包含未处理事件，延迟事件单独归入“延迟”Tab。

## 已确认的产品行为

- 左侧导航只保留“事件篮”和“行动”。
- 事件篮 Tab 顺序为：`待处理`、`已转项目`、`已委托`、`延迟`、`已放弃`、`已完成`。
- “待处理”只匹配 `Event.status === 0`，不包含延迟事件。
- “已转项目”展示项目卡片，而不是重复展示已转项目的来源事件。
- “已转项目”直接展示项目卡片，不再提供项目状态二级筛选；已放弃事项在“已放弃”Tab 展示。
- 项目卡片保留现有能力：展开/收起详情、查看行动、编辑项目、添加/编辑/删除行动、完成项目、放弃项目、删除项目。
- 项目卡片可展开查看；放弃后的事项通过“已放弃”Tab 查看。
- 删除项目继续使用现有后端语义：删除来源事件及其项目行动，并保留当前确认提示。
- 事件处理、项目操作和行动操作成功后刷新相关列表；事件处理完成后保留当前页面反馈并切换到结果对应的 Tab（若当前交互没有明确目标，则停留在当前 Tab）。

## 页面结构

事件篮页面保留现有标题、副标题和快速新增事件区域。快速新增区域下方改为一组横向平铺的 Tab，每个 Tab 展示对应数量，当前 Tab 使用 Ant Design Tabs 的选中状态。

事件 Tab 的数据映射如下：

| Tab | 数据条件 | 内容 |
| --- | --- | --- |
| 待处理 | `status === 0` | EventRow |
| 已转项目 | 项目卡片 | ProjectCard |
| 已委托 | `status === 2` | EventRow |
| 延迟 | `status === 3` | EventRow |
| 已放弃 | `status === 4` | EventRow |
| 已完成 | `status === 5` | EventRow |

“已转项目”Tab 不使用事件状态条件，而是加载 `projectsApi.list()` 和 `actionsApi.list()`，展示可见项目并按 `project_id` 将行动分组。已放弃事项统一在“已放弃”Tab 展示。Tab 的数量显示项目数量；其他 Tab 的数量显示事件数量。

当当前 Tab 没有数据时，使用与内容类型对应的空状态：事件 Tab 显示事件提示，项目 Tab 显示“还没有项目”。加载项目数据时显示项目区域的加载状态，不阻塞其他事件 Tab 的基本渲染；请求失败使用现有页面级错误提示。

## 组件与数据边界

为避免事件篮和旧项目页维护两份项目行为，将项目展示和操作拆分为可复用组件，建议边界如下：

- `ProjectCard`：负责项目摘要、状态、优先级、行动进度、展开状态和项目级操作回调。
- `ProjectActionList`：负责目标展示、行动列表和行动级操作回调。
- `ProjectActionModal`：负责项目范围内行动的新建/编辑表单，新建时固定传入当前 `project_id`，不显示关联事项选择。
- `ProjectModal`：负责项目编辑表单。
- `AbandonModal`：负责放弃项目原因表单。

上述组件只接收实体数据和明确的回调，不直接管理事件篮 Tab 状态。页面容器负责调用 API、刷新数据和展示成功/失败反馈。若现有 `Projects.tsx` 已包含这些组件，应提取到 `src/components/projects/` 下复用；不进行与本需求无关的组件重构。

事件篮页面的状态包括：事件列表、项目列表、行动列表、当前主 Tab、项目状态筛选、展开的项目 ID、编辑/新增/放弃弹窗状态、加载状态和错误信息。切换到“已转项目”Tab 时，如果项目和行动尚未加载则请求一次；成功的项目/行动变更刷新两者，并同步项目 Tab 数量。

## 路由与导航兼容

- 从 `Layout` 的导航项移除 `/projects`，使用户不可见地进入独立项目页。
- `/inbox` 成为项目卡片的唯一可见入口。
- 已存在的 `/projects` 路由不再作为导航入口；为避免旧书签失效，可以将其改为重定向到 `/inbox`，不再渲染第二套项目页面。
- `Actions` 页继续保留，行动从项目入口创建并管理生命周期，不提供手动选择关联事项。

## 样式要求

- 主 Tab 使用平铺的横向布局，不嵌套在卡片中，不使用下拉框替代。
- Tab 在窗口较窄时允许横向滚动，不能压缩到文字重叠。
- 项目卡片沿用现有卡片和项目行动区域样式；事件卡片沿用现有事件操作。
- 项目 Tab 不设置二级项目状态筛选。
- 保持现有 Ant Design 主题、蓝色主色、32px 控件高度和响应式布局。

## 错误处理与边界情况

- 事件、项目或行动 API 失败时显示现有 `Alert` 页面错误，不清空已经成功加载的数据。
- 项目或行动 mutation 失败时保持弹窗打开，允许用户修正后重试；成功后关闭弹窗并刷新列表。
- 项目 Tab 在项目数据加载期间显示加载状态；切换回事件 Tab 不应触发重复请求。
- 删除来源事件、删除项目和删除行动都继续使用当前 `Popconfirm`，不改动后端数据语义。
- 如果项目行动列表为空，展开后显示空状态；进行中项目仍显示添加行动按钮。
- 旧 `/projects` 地址不会暴露独立项目视图，避免数据操作入口分裂。

## 验收与测试

1. `npm run build` 通过，且不存在 TypeScript 类型错误。
2. 左侧导航只显示事件篮和行动；访问 `/projects` 时重定向到 `/inbox`。
3. 事件篮 Tab 为平铺样式，待处理不包含延迟事件，延迟 Tab 能显示延迟事件。
4. 各事件 Tab 的数量与对应状态事件数量一致；事件增删改和处理后数量更新。
5. 已转项目 Tab 能展示项目卡片；已放弃事项可在事件篮“已放弃”Tab 查看。
6. 项目卡片默认收起；展开后可查看行动，且项目和行动的编辑、添加、删除、完成、放弃行为与原项目页一致。
7. 放弃事项可在“已放弃”Tab 查看；行动只能从项目入口创建。
8. 宽度较窄时 Tab、项目卡片和操作按钮不发生文字或控件重叠。
9. `cargo check --manifest-path src-tauri/Cargo.toml` 与 `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` 保持通过，Rust 层无业务修改。
