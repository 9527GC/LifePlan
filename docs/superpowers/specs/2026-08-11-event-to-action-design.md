# 事件到行动闭环设计

## 1. 背景与目标

第一阶段打通 LifePlanTodolist 的核心闭环：

`事件篮 -> 事件处理 -> 项目或委托行动 -> 行动执行`

本阶段在现有 Tauri 2、React、TypeScript、Rust 和 SQLite 架构上增量改造，不重写数据层。界面采用简洁、清新的 Ant Design 风格，主色为 `#1778FF`，优先适配桌面窗口 `800x600` 及更大尺寸。

第一阶段包含：

- 事件篮的创建、编辑、处理、筛选、删除和恢复。
- 事件转项目、项目状态操作和事件状态联动。
- 委托跟进行动。
- 完整行动页：查看、筛选、新建、编辑、完成、恢复和删除。
- 项目清单的基础查看、筛选、编辑、完成、放弃和删除。
- 示例数据不作为本阶段必需功能，不纳入本阶段验收。

本阶段不包含：

- 任务/子任务层级；产品固定为项目-行动两层。
- 独立目标对象和目标规划页面。
- 每日清单、番茄钟、奖励池和复盘统计。

## 2. 核心对象关系

事件和项目是两个独立对象，但组成一条事项链路：

`事件 1 -- 0..1 项目 -- 多条行动`

行动可以是：

- 无关联行动：不关联事件和项目。
- 事件行动：只关联尚未转项目的事件。
- 项目行动：只关联项目，项目通过来源关系归属于事件。

一个事件最多转成一个项目。事件转成项目后，不允许再创建直接关联该事件的行动。事件转项目时，已有直接事件行动全部迁移到项目下，之后不再直接关联事件。

事件不再有说明或目标字段。项目目标是项目自己的可选多行文本，转项目时手动填写，创建后可以编辑或清空。

## 3. 状态与业务规则

### 3.1 事件状态

事件状态为：

- `未处理`
- `已转项目`
- `已委托`
- `延迟`
- `已放弃`
- `已完成`

事件篮筛选为：`待处理 / 已转项目 / 已委托 / 延迟 / 已放弃 / 已完成`。

`未处理`和`延迟`归入待处理。延迟事件显示在待处理列表底部；到重新处理日期后自动恢复为`未处理`。已处理事件保留在历史列表中。

事件完成与历史保留：

- 放弃事件保留在事件篮“已放弃”Tab，不再进入行动清单。
- 已完成事件保留在“已完成”Tab。

已转项目的事件由项目状态同步，不再创建或完成直接事件行动。

### 3.2 项目状态

项目状态只有：

- `进行中`
- `已完成`
- `已放弃`

项目只能从事件转化创建，不能独立创建。项目完成条件是至少有一条行动，且所有行动为`已完成`或`已放弃`。满足条件后显示“可完成”按钮，确认后标记项目完成，并同步来源事件为`已完成`。

项目放弃时必须填写原因。项目和来源事件同步变为`已放弃`，共用同一个放弃原因，项目下所有待办行动级联为`已放弃`。

项目恢复只从事件篮进入。恢复时来源事件、项目，以及本次级联放弃的行动恢复；之前已单独放弃的行动保持`已放弃`。

### 3.3 行动状态

行动状态为：

- `待办`
- `已完成`
- `已放弃`

行动默认列表只显示待办。用户可以通过筛选查看全部、已完成或已放弃。

用户不能直接把行动标记为已放弃；行动只有在事件或项目放弃时由系统级联变为已放弃。已完成行动可以恢复为待办，恢复时清空 `completed_at`；再次完成时记录新的完成时间。

完成项目或事件下的行动不会自动修改其他对象，委托跟进行动完成后的特殊处理除外。

## 4. 事件篮交互

### 4.1 新建和编辑

新建事件表单只有：

- 标题，必填。

事件创建后只保存标题，必须通过“自己做”转为项目后才能创建行动。事件编辑弹窗支持编辑标题，不支持直接编辑状态。

每条事件提供：

- 编辑标题。
- 处理。
- 不提供事件级直接新建行动入口；行动必须从项目中创建。
- 删除。
- 对已放弃事件提供恢复。
- 对满足条件的事件提供完成确认。

删除事件的级联规则：

- 尚未转项目的事件及其直接行动一起删除。
- 已转项目的事件、来源项目及项目下全部行动一起删除。
- 已处理事件也允许删除。

### 4.2 处理弹窗

处理弹窗提供四个去向：`自己做 / 委托 / 延迟 / 放弃`。

#### 自己做

字段：

- 项目标题：默认事件标题，可修改。
- 项目目标：选填，多行文本。
- 预计耗时：下拉选择 `30分钟 / 1小时 / 1.5小时 / 2小时`，默认 `1小时`。
- 开始日期：选填。
- 截止日期：选填。
- 重要程度：重要 / 不重要，必填。
- 紧急程度：紧急 / 不紧急，必填。
- 初始行动标题：事件没有直接行动时必填。

如果事件已有任何直接行动，转项目时迁移全部行动并保留原字段和状态，不创建额外初始行动。如果事件没有直接行动，则创建一条初始行动。初始行动默认预计耗时为 `1小时`，继承项目的重要程度、紧急程度、开始日期和截止日期；行动优先级独立计算。

项目初始状态为`进行中`。事件状态变为`已转项目`。

日期同时填写时，截止日期不得早于开始日期。

#### 委托

字段：

- 委托对象：必填文本。
- 跟进日期：必填日期，只精确到日期，保存为跟进行动的开始日期。
- 跟进说明：选填，保存到行动说明。
- 行动标题：默认`跟进：事件标题`，允许修改。

创建一条正式行动，固定直接关联原事件，标记为委托跟进行动。跟进行动默认不重要、不紧急、预计 `1小时`、非青蛙，截止日期留空。事件状态变为`已委托`。

委托跟进行动创建后只能编辑标题、说明、日期、耗时、重要程度、紧急程度和青蛙标记，不能修改关联对象。

跟进行动完成时弹出：

- 保持已委托：行动完成，事件保持已委托。
- 标记事件已完成：要求事件满足完成条件，确认后事件完成。
- 标记事件已放弃：要求填写放弃原因，确认后事件和其关联数据按放弃规则处理。

删除委托跟进行动时，原事件自动恢复为`未处理`。

#### 延迟

字段：

- 重新处理日期：选填日期。
- 延迟备注：选填文本。

事件状态变为`延迟`，保留在待处理列表底部。再次处理时可重新选择四种去向。到重新处理日期后自动恢复为`未处理`。

#### 放弃

放弃原因必填。事件状态变为`已放弃`。如果事件已有项目，项目同步放弃；项目及事件关联的待办行动全部级联为已放弃，已完成行动保持不变。

恢复已放弃事件前需要确认，并说明项目和级联行动会恢复。恢复后只恢复本次级联放弃的数据。

## 5. 已转项目 Tab 交互

项目统一展示在事件篮“已转项目”Tab 中；不设置独立项目导航或项目状态二级筛选。已放弃事项在事件篮“已放弃”Tab 展示。

每个项目显示：

- 标题。
- 目标。
- 预计耗时。
- 开始日期和截止日期。
- 重要/紧急状态和四象限。
- 行动完成进度。
- 项目状态。
- 来源事件。

项目列表直接编辑标题、目标、预计耗时、日期、重要程度和紧急程度。项目标题在转化后独立维护，不随事件标题变化；项目目标也独立维护。

项目行提供：

- 可完成时显示完成操作，确认后完成并同步事件。
- 放弃操作，弹窗要求填写原因。
- 删除操作。

项目删除规则：有行动时只能选择“取消”或“删除项目和全部行动”；没有行动时可以直接删除。删除项目同时删除来源事件。

示例数据不作为当前阶段必需功能，也不纳入本阶段验收；后续如启用，必须使用完整项目-行动链路。

## 6. 行动页交互

行动页默认显示待办行动，排序为：

1. 优先级从高到低。
2. 有日期的行动优先。
3. 日期从近到远。
4. 无日期行动放在有日期行动之后。
5. 同条件下按创建时间排序。

筛选项：

- 状态：`全部 / 待办 / 已完成 / 已放弃`。
- 是否青蛙。

行动行显示标题、状态、优先级、日期、委托跟进标签和对象、青蛙标记。委托跟进行动显示“委托跟进”标签、关联事件标题和委托对象。

### 6.1 新建行动

新建行动不手动选择关联类型。用户从项目卡片进入新建行动时，系统自动关联当前项目；不提供无关联行动或直接关联事件的入口。

关联关系由项目入口决定，创建后不能修改。行动字段为：标题、说明、预计耗时、开始日期、截止日期和青蛙。标题必填；耗时默认 `1小时`；日期均选填，同时填写时截止日期不得早于开始日期。

项目行动遵循项目的二值重要程度和紧急程度设置。

### 6.2 编辑、完成和删除

行动编辑支持除关联类型和关联对象外的所有字段。普通行动即使完成后仍可编辑；委托跟进行动保持固定关联原事件。

完成行动时设置状态和 `completed_at`。删除行动前需要确认。项目下最后一条行动不能删除；未转项目事件的最后一条直接行动可以删除，但事件之后不能完成，直到重新创建行动。

已完成行动恢复为待办时：

- 清空 `completed_at`。
- 如果所属项目已完成，项目恢复为`进行中`，来源事件恢复为`已转项目`。
- 未转项目的已完成事件新增待办行动时，事件恢复为`未处理`。

## 7. 数据库与后端实现

沿用 Rust `rusqlite` 和 Tauri 命令。跨对象操作必须在 SQLite 事务中完成，前端不自行推断联动状态。

事件表保留/新增：

- `id`, `title`, `status`, `delegated_to`, `follow_up_date`, `delay_until`, `delay_note`, `abandon_reason`, `created_at`, `updated_at`。

删除事件字段：

- `description`, `decision`。

项目表调整：

- `event_id` 改为必填且唯一。
- 新增 `target`。
- 删除 `goal_id`, `description`。
- 保留预计耗时、日期、重要/紧急、优先级、优先级模式、状态和时间字段。

行动表调整：

- `project_id` 改为可空。
- 新增可空 `event_id`。
- 新增 `completed_at`、`is_delegated_follow_up`、`cascade_abandoned`。
- 保留标题、说明、耗时、日期、青蛙、状态和时间字段。

旧目标模型、目标 API 和目标页面移除。由于当前工作区没有可用 Git 仓库，不能提交设计文档；实现时以本设计文档为依据，并保留现有数据迁移的兼容处理。

后端事务命令至少覆盖：

- 事件/行动的增删改查。
- 事件转项目。
- 委托跟进行动创建和完成后的事件处理。
- 项目增删改查和状态操作。
- 事件/项目完成、放弃、恢复。
- 项目-行动数据初始化规则（示例数据不作为本阶段必需项）。

## 8. 验收标准

- 新建事件后可以分别执行自己做、委托、延迟和放弃。
- 自己做可以创建项目，并正确迁移已有事件行动或创建初始行动。
- 委托可以创建可执行的跟进行动，并在行动完成时处理原事件。
- 延迟事件可重新处理，到期自动恢复未处理。
- 事件、项目、行动的完成、放弃、恢复联动符合上述规则。
- 行动页支持完整筛选、新建、编辑、完成、恢复和删除。
- 项目页支持筛选、编辑、完成、放弃和删除。
- 不再出现事件说明、事件目标、独立目标和项目说明字段。
- 新数据库首次打开进入事件篮；示例数据不作为本阶段验收项。
- 页面在 `800x600` 下可用并允许滚动，更大窗口自适应。
- `npm run build` 通过；核心事务和状态联动有针对性验证。
