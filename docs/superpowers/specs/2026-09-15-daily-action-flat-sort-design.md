# 今日事安排行动平铺模式排序优化设计

## 背景

今日事页面的“安排行动”弹窗支持平铺视图和按事件视图。当前平铺视图直接使用筛选后的行动数组顺序展示，没有按照行动开始日期和优先级进行统一排序，导致有开始日期与无开始日期的行动混排，同日期行动的优先级也不明确。

## 目标

优化平铺视图的行动排序，使用户能优先看到更早开始、优先级更高的行动，同时不改变按事件视图和项目行动自身的手动排序语义。

## 排序规则

平铺视图中，行动按以下字段依次排序：

1. 有开始日期的行动优先于没有开始日期的行动。
2. 都有开始日期时，按 `start_date` 升序排列，较早日期在前。
3. 开始日期相同时，按 `priority` 升序排列，即 P1、P2、P3、P4。
4. 开始日期和优先级均相同时，保持接口返回的原始相对顺序，避免列表无意义跳动。

搜索只负责筛选，筛选结果仍使用上述排序规则。

## 非目标与兼容性

- 不改变按事件视图的分组方式和分组内 `sort_order` 排序。
- 不改变数据库字段、API 接口或行动自身的 `sort_order`。
- 不改变“当日已安排”标记、选中状态和行动分配行为。
- 不对开始日期早于或晚于当前日期的行动做额外过滤；日期仅用于排序。

## 实现方案

在 `src/pages/DailyList.tsx` 所在模块中增加一个纯排序函数，接收行动数组并返回排序后的新数组，不原地修改输入数组。平铺视图使用该排序结果渲染；事件视图继续接收原有的筛选结果。

排序函数使用带原始索引的稳定排序，避免 JavaScript 运行环境或后续改动导致相同日期、相同优先级的行动顺序不稳定。

## 验证

增加针对排序函数的单元测试，覆盖：

- 有开始日期的行动排在无开始日期行动之前；
- 开始日期较早的行动排在较晚日期之前；
- 同一天按 P1 到 P4 排列；
- 日期和优先级相同时保持原始顺序；
- 空数组和单元素数组；
- 输入数组不会被原地修改。

同时执行 TypeScript 构建，确认平铺视图和事件视图均可正常编译。
