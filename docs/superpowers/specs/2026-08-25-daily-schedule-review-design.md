# 每日日程清单与复盘设计

## 目标

将每日清单从“行动列表”升级为按时间安排和复盘的日程工作台。页面需要在桌面窗口中尽量展示完整一天，同时保留已有行动库、行动完成状态和每日复盘记录之间的清晰边界。

## 已确认规则

- 每个时间段只能安排一个行动。
- 同一个行动可以安排到多个日期，也可以在同一天的多个时间段重复安排。
- 同一天的时间段不允许重叠。
- 默认模板范围为 `08:30-18:00`。
- 除 `12:00-13:30` 外，其余默认时间段均为 30 分钟。
- `12:00-13:30` 是普通时间段，可以安排行动和填写复盘。
- 新日期第一次打开时自动复制当前模板。
- 已存在日期的时间段不会随模板更新自动变化。
- 当天可以新增、删除和调整时间段，也允许扩展到默认范围之外。
- “保存为模板”只保存当天的开始时间和结束时间，覆盖旧模板，不保存行动和复盘。
- 删除时间段只删除当天排程及该时间段复盘，关联行动保留。
- 复盘只能手动点击触发，不根据时间自动弹窗或改变状态。
- 复盘提交时三个字段都必填：实际工作情况、是否达到预期、是否专注。
- 复盘不会自动完成行动；只有显式点击“完成行动”才同步全局行动状态。

## 页面布局

每日清单采用 Ant Design 风格的固定行高日程表，而不是按时长撑高的日历卡片。默认一天 17 行，每行固定 `36px`，午休段也只占一行。这样优先保证一天的整体可扫描性；完整内容在详情弹框中查看。

表格为三列：

1. `时间段`
2. `计划行动`
3. `复盘`

表格最小宽度由内容决定。窗口较窄时允许横向滚动，不压缩标签和时间；正文超长时单行省略。

### 计划行动列

计划单元格的标签与标题必须在同一行，顺序为：

```text
重要 / 紧急 / 青蛙 + 行动标题
```

行动标签不改变整行布局：重要使用橙色标签，紧急使用红色标签，青蛙使用绿色标签。计划状态使用整格背景：空时间段保持白色，已安排但未完成使用浅蓝色，关联行动已完成使用浅绿色，已放弃或保留但不再执行的时间段使用浅灰色。

空时间段点击后直接打开“选择或新建行动”入口。入口支持搜索已有行动，也支持输入标题后直接创建新行动并绑定到当前时间段。已安排时间段点击后打开统一详情弹框。

### 复盘列

复盘是独立列，与计划行动按时间段横向对齐。复盘列不使用独立状态色块，保持白色或浅灰表格背景，避免与计划状态产生第二套颜色语义。

复盘单元格的标签与文本必须在同一行，顺序为：

```text
预期 / 专注 + 实际工作情况摘要
```

未复盘时显示灰色“待复盘”标签和点击提示。已复盘时显示两个结果标签，实际工作情况以单行摘要展示，完整文本在详情弹框中查看。预期和专注的标签文字明确显示“是/否”，颜色只作为辅助：是使用成功或信息色，否使用错误色。

点击复盘单元格或已安排的时间段都进入同一个时间段详情弹框。

## 时间段交互

- 时间段之间悬停显示行间 `+` 插入控制，点击后在当前位置插入一个时间段。
- 新增和编辑时间段使用开始时间、结束时间选择器；结束时间必须晚于开始时间。
- 日程中支持拖拽时间段顶部或底部边界，按 30 分钟网格快速调整。
- 详情弹框支持精确修改时间，适用于非标准时长。
- 所有新增和调整都先进行同日重叠校验；冲突时阻止保存并明确提示冲突时间。
- 删除时间段需要确认，只删除该日期的排程记录，不删除行动。

## 时间段详情弹框

详情弹框集中处理一个时间段的全部操作：

- 开始时间和结束时间
- 选择、更换或新建行动
- 查看行动的项目、重要程度、紧急程度、青蛙标记
- 显式“完成行动”或“恢复行动”
- 复盘字段：实际工作情况、是否达到预期、是否专注
- 保存复盘、取消编辑、删除时间段

复盘保存按钮在三个字段未完成时不可提交或显示对应校验错误。保存复盘只更新该时间段的复盘，不改变行动全局状态。

## 数据模型

每日时间段是独立的排程实体，行动是被引用的全局实体。建议新增两张表：

### `daily_schedule_days`

用于表示某个空间中的某个日期已经初始化，避免模板更新时重新覆盖已存在日期。

- `id`
- `space_id`
- `list_date`
- `created_at`
- 唯一约束：`space_id + list_date`

### `daily_schedule_slots`

保存某天的时间段、行动引用和复盘。

- `id`
- `space_id`
- `list_date`
- `start_time`
- `end_time`
- `action_id`，可为空
- `actual_notes`，实际工作情况
- `met_expectation`，可空的 0/1
- `focused`，可空的 0/1
- `sort_order`
- `created_at`
- `updated_at`

同一空间同一天的时间段按 `start_time` 排序，并通过命令层校验禁止重叠。行动关联不设置当天唯一约束，因此允许同一天重复安排。

### `daily_schedule_templates`

保存当前模板的时间结构，不保存行动和复盘。

- `id`
- `space_id`
- `start_time`
- `end_time`
- `sort_order`
- `updated_at`

保存模板时在事务中替换当前空间的模板时间段。初始化新日期时复制模板行到 `daily_schedule_slots`，不复制行动和复盘。

## API 边界

前端 API 应提供以下能力：

- 获取某日完整时间段及关联行动、复盘
- 初始化某日并返回时间段
- 创建、更新、删除时间段
- 调整时间段顺序/时间并进行冲突校验
- 设置或清除时间段行动
- 保存和读取模板
- 保存时间段复盘

行动完成和恢复继续调用现有行动命令，保证每日清单与全局行动列表状态一致。

## 错误处理

- 日期格式、时间格式非法时返回明确错误。
- 开始时间不早于结束时间时拒绝保存。
- 时间段发生重叠时拒绝保存，并提示冲突的已有时间段。
- 绑定的行动不存在或已删除时拒绝绑定，并刷新当前日期数据。
- 复盘字段缺失时在弹框内显示字段级校验，不丢失已填写内容。
- 排序或保存失败时恢复本地乐观更新前的顺序/内容，并提示用户重试。

## 实现范围

- 新增每日时间段与模板的 SQLite 迁移、Rust 模型和命令。
- 将现有每日清单页面替换为固定行高三列表格日程视图。
- 保留现有侧边栏“每日清单”入口和日期切换。
- 复用现有 Ant Design 主题、Modal、Tag、DatePicker、Select、Form 和提示组件。
- 不改变事件篮、项目、全局行动的既有业务规则。

## 验证

- TypeScript/Vite 构建通过。
- Rust `cargo check` 通过。
- 新日期自动生成当前模板；已存在日期不受模板更新影响。
- 默认 17 个时间段均为固定 36px，午休也是单行。
- 空时间段可以选择已有行动或新建行动；同一行动可重复安排。
- 新增、删除、编辑、拖拽调整时间段可用，重叠时间段被阻止。
- 复盘列保持独立且不填充状态色；标签和文本同一行。
- 复盘三个字段必填，保存后刷新仍保留。
- 完成行动后全局行动列表同步完成；删除排程不删除行动。
