# 项目行动列表拖动排序设计

## 目标

让项目详情中的行动列表能够稳定拖动排序，并在拖动过程中清楚表达当前的插入位置，让用户知道松手后行动会落在目标行动之前还是之后。

## 交互设计

- 进行中的项目且至少有两个行动时允许排序；已完成项目、已放弃项目或只有一个行动时不允许排序。
- 左侧抓手是明确的拖动入口，行动行本身继续作为拖动承载区域。
- 开始拖动后，被拖动行动半透明，列表标题区域显示正在调整顺序的状态。
- 拖动经过目标行动时，以鼠标在目标行上下半区为依据：上半区显示目标行上方的插入线，下半区显示目标行下方的插入线，并同步显示位置文字。
- 不允许把行动放置在自身位置；离开列表或取消拖动时清除所有插入提示。
- 松手后先更新本地列表，再调用现有 `reorder_project_actions` 接口保存。
- 保存成功提示移动后的相对位置；保存失败恢复拖动前顺序并显示错误。

## 实现范围

- 修改 `src/pages/Projects.tsx` 中的 `ProjectActionList` 拖动状态、事件处理和位置提示。
- 修改 `src/App.css` 中的拖动中、插入上方、插入下方及状态文案样式。
- 继续使用现有后端排序接口和 `sort_order` 字段，不修改数据库及 Rust 命令。

## 验证

- 执行 TypeScript/Vite 构建，确认类型检查和生产构建通过。
- 在项目详情中验证：向上移动、向下移动、移动到首项、移动到末项、取消拖动、保存失败恢复。
- 确认排序刷新后仍保持，且其他项目行动列表不受影响。
