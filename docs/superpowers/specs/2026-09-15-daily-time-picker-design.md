# 今日事时间段选择器改造设计

- 日期：2026-09-15
- 状态：待用户评审

## 背景

“今日事”新增和编辑时间段目前使用 Ant Design `TimePicker`，小时和分钟分别以两列选择。希望改为参考截图的组合时间列表形式，降低选择成本并让候选值更直观。

## 目标

1. 新增时间段和编辑时间段统一使用组合时间候选项。
2. 候选项按 `HH:mm` 展示，时间粒度为 30 分钟。
3. 点击候选时间后立即完成该字段选择并关闭下拉面板，无需点击“确定”。
4. 下拉面板底部仅保留“此刻”按钮。
5. 保持现有表单校验、保存、拆分、删除和数据格式不变。

## 非目标

- 不修改时间段数据结构或后端接口。
- 不改变时间段必须满足结束时间晚于开始时间的校验。
- 不改变新增时间段的默认值、插入逻辑或保存模板逻辑。
- 不支持任意分钟输入；候选值固定为半小时刻度。

## 交互设计

### 候选列表

- 生成全天候选值：`00:00、00:30、01:00、01:30……23:30`。
- 每个候选项以完整的 `HH:mm` 单行展示。
- 下拉列表支持滚动；打开时尽量定位到当前值附近，保持现有时间选择器的可用性。
- 当前值在列表中保留选中态，视觉上与普通候选项区分。

### 选择行为

- 点击任意候选项：立即写入表单字段、关闭下拉面板。
- 不显示默认“确定”按钮，也不要求二次确认。
- 点击“此刻”：使用当前系统时间计算到半小时刻度的时间值，写入字段并关闭面板。
- “此刻”的取整规则：当前分钟小于 15 取整到当前小时 `:00`，大于等于 15 且小于 45 取整到 `:30`，大于等于 45 进位到下一小时 `:00`；跨越 24:00 时回到 `00:00`。

### 表单提交

- 时间字段仍以现有 `Dayjs` 值参与表单提交。
- 新增与编辑组件均复用相同的时间选择器实现和样式。
- “取消”“保存时间段/保存”等弹窗底部操作保持不变；这里的“底部仅保留此刻按钮”仅指时间下拉面板底部。

## 技术方案

采用方案 A：继续使用 Ant Design `TimePicker`，通过自定义面板/面板渲染能力实现组合时间列表，并保留现有表单集成。

实现要点：

1. 封装一个用于新增和编辑的半小时刻度时间选择器，避免两处实现分叉。
2. 使用统一的候选值生成函数，确保边界值固定为 `00:00` 至 `23:30`。
3. 通过选择事件立即更新值并关闭面板；隐藏确认操作。
4. 自定义面板底部，仅渲染“此刻”按钮。
5. 补充列表、选中态、滚动区域和底部操作的局部样式，沿用项目现有视觉规范。
6. 保持未提交的其他工作区修改不被覆盖或纳入本次提交。

## 校验与验收

- 新增时间段的开始、结束字段均显示组合时间列表。
- 编辑时间段的开始、结束字段均显示组合时间列表。
- 候选项间隔始终为 30 分钟。
- 点击候选项后无需点击确认即可看到字段值更新，且下拉立即关闭。
- “此刻”可正常写入半小时刻度值并关闭下拉。
- 现有结束时间晚于开始时间的校验仍然有效。
- 新增、编辑、保存、取消、拆分、删除流程无回归。
- `npm run build` 通过。

## 风险与兼容性

Ant Design 版本为项目当前使用版本，时间选择器的面板定制 API 可能存在类型或行为差异。实现时优先使用该版本公开 API；若公开 API 无法可靠实现“点击即关闭”，则在不改变外部表单接口的前提下，以受控方式封装下拉开关状态完成同等交互。
