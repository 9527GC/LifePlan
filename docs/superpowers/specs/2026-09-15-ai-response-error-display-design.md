# AI 响应错误展示优化设计

日期：2026-09-15

## 目标

优化工作日志生成失败时的响应展示，保留服务商返回的真实错误信息，区分 HTTP、网络和响应格式问题，同时避免泄露 API Key。

## 范围

修改 `src/components/ui/WorkLogModal.tsx` 的 AI 请求与错误展示，不改变成功生成逻辑和配置存储方式。

## 方案

1. 请求完成后先读取响应文本，再尝试解析 JSON，避免非 JSON 响应覆盖真实 HTTP 错误。
2. 将错误归类为 HTTP 错误、网络错误、响应格式错误和未知错误。
3. 对 400、401、403、404、429 等常见状态提供中文说明，并附带服务商原始错误文本。
4. 在工作日志弹窗中显示简洁错误摘要，并提供详情弹窗查看请求地址、状态码、时间和脱敏后的响应原文。
5. 在控制台输出完整诊断信息；请求头和 API Key 不进入日志或页面。
6. 对超长响应进行截断，避免错误详情撑破界面。

## 验收标准

- 非 JSON 错误响应能显示 HTTP 状态码及原始文本。
- `Failed to fetch` 等网络异常能显示网络/CORS 方向的提示。
- 服务返回无 `choices[0].message.content` 时能明确提示响应格式不兼容。
- 详情展示不包含 API Key。
- TypeScript 检查和 Vite 构建通过。
