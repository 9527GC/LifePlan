# 今日事行动详情标记青蛙设计

## 背景

“今日事”页面中，用户点击已安排行动后可以查看行动详情。当前详情弹框只能查看行动信息、切换行动或开始番茄钟，用户无法在此处快速调整青蛙行动标记。项目已有行动字段 `is_frog`、更新行动接口以及 `FrogHelp` 提示组件。

## 目标

在已安排行动的详情弹框左下角提供“标记为青蛙”复选框及青蛙法则提示，并支持即时保存：

- 打开详情时，复选框状态与行动当前的 `is_frog` 值一致；
- 勾选后立即将行动标记为青蛙行动；
- 取消勾选后立即恢复为普通行动；
- 更新成功后，详情内容和今日事列表中的行动标签同步反映最新状态；
- 更新失败时恢复原状态并提示用户。

## 交互设计

详情弹框底部采用左右布局：

- 左侧：`标记为青蛙` 复选框，后接现有 `FrogHelp` 提示图标；
- 右侧：保留“更换行动”和“开始番茄钟”按钮；
- 复选框在更新请求期间禁用，避免重复提交；
- 成功后保留详情弹框打开，并立即显示最新行动信息；
- 失败后恢复切换前状态，通过现有错误处理方式显示错误消息。

## 技术方案

### 前端状态

在 `ActionPickerModal` 中增加用于表示青蛙标记更新状态的本地状态，初始值由 `slot.action.is_frog === 1` 得出。通过受控 `Checkbox` 处理变化事件。

### 数据更新

复用 `actionsApi.update` 和现有 `UpdateAction` 类型。提交时保留行动原有可编辑字段，仅将 `is_frog` 替换为 `1` 或 `0`，避免修改标题、时间、优先级等其他属性。

更新成功后：

1. 使用接口返回的完整行动替换当前 slot 中的行动；
2. 通过现有 `onSaved` / `refreshSlot` 回调更新父级日程状态；
3. 保证详情弹框继续展示更新后的行动。

由于父级 `actions` 列表当前由加载结果维护，更新成功后同时更新列表中的对应行动，确保再次打开详情及今日事单元格都使用最新数据。

### 失败处理

调用失败时不改变已持久化的状态，将复选框恢复到更新前值，并使用 `userFacingError` 转换错误后调用 `message.error`。

## 范围与非目标

- 仅影响“今日事”中已安排行动的详情弹框；
- 不改变新建或编辑行动弹框已有的青蛙标记功能；
- 不改变重复行动模板的青蛙标记逻辑；
- 不新增数据库字段或后端命令；
- 不调整青蛙行动的排序规则和其他页面展示规则。

## 验收标准

1. 打开普通行动详情，左下角显示未勾选的“标记为青蛙”和提示图标。
2. 勾选后，行动详情和今日事列表均显示“青蛙”标签，重新打开仍保持勾选。
3. 打开青蛙行动详情，复选框默认已勾选。
4. 取消勾选后，详情和今日事列表立即去除“青蛙”标签，重新打开保持未勾选。
5. 更新请求失败时，复选框回滚并出现可理解的错误提示。
6. 更新过程中不能重复触发请求，原有“更换行动”和“开始番茄钟”功能不受影响。
