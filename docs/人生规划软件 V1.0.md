# 产品定位
一款基于《小强升职记》理念的桌面时间管理工具，帮助用户从"事件收集"到"四象限决策"，再到"项目拆解"和"每日行动执行"，形成完整闭环。

V1.0 聚焦个人使用，所有数据本地存储，不依赖云端。

# 主界面结构

底部/顶部导航包含 4 个主要入口：

1. **事件篮**：收集所有事件，包含子视图：
   - 待处理：未决策的事件
   - 将来/也许：延迟的事件
2. **已转项目**：项目作为事件篮中的一个 Tab 展示，项目直接拆解为行动
3. **行动**：所有下一步行动列表
4. **每日 / 复盘**：每日工作清单、番茄钟、复盘和统计功能

---

# 核心设计原则

## 事件就是项目
事件篮中的每条事件，直接视为一个"项目"。

在四象限决策时，需要分析该事件对应的人生目标，再判断：
- 做不做？
- 谁做？（自己 / 他人 / 放弃）
- 如果自己做，拆解为任务和行动。

## 目标驱动
所有项目必须归属于某个目标。没有目标的项目，先放入"待明确目标"区，不进入行动清单。

## 极简原则
V1.0 不做角色责任、情境标签等复杂概念，只保留最必要的要素：目标、项目、任务、行动、番茄钟、复盘。

# 功能模块

## 一、事件篮（Inbox）
脑中任何念头、任务、约定，先丢进事件篮。所有的事都先记在这里，放空大脑。

当专注工作时，临时有事，不中断工作，扔进事件篮。

### 新用户首次启动
新用户首次打开应用时，直接进入事件篮页面，无需先创建目标。示例数据不作为当前阶段的必需功能，是否提供示例链路由后续首次使用体验另行确定。

### 事件到项目的流转
事件篮中的事件，经过决策后在事件篮的“已转项目”Tab 中进入项目-行动流程：

**方式一：在事件篮发起**
1. 用户在事件篮中点击"设为项目"或标记为"自己做"。
2. 系统在事件篮的“已转项目”Tab 中展示该项目，并自动打开项目处理区域。
3. 用户在项目中设置目标、重要程度、紧急程度。
4. 系统自动计算优先级，允许用户手动调整。
5. 该项目正式进入“已转项目”Tab。

**方式二：在已转项目 Tab 查看**
1. 已转项目统一在事件篮的“已转项目”Tab 中查看。
2. 用户在项目卡片中编辑目标、重要程度、紧急程度和行动。

事件篮中的事件还可以选择：
- **委托**：进入事件篮的“已委托”Tab，生成一条跟进行动，记录指派对象和截止日期。
- **延迟/将来**：留在事件篮的"将来/也许"子视图，不参与日常安排。
- **放弃**：进入事件篮的“已放弃”Tab，保留历史记录，不进入行动清单。

### 字段
- 标题
- 创建时间
- 备注
- 状态：待梳理 / 已决策 / 已转为项目
- 决策去向：自己做 / 委托 / 延迟 / 放弃

---

## 二、四象限决策台
对事件篮中的项目按"重要 × 紧急"分类，并决定去向。

四象限法则：
- 重要且紧急：立即做
- 重要不紧急：有计划地去做（重点投入）
- 不重要紧急：交给别人做
- 不重要不紧急：尽量不做或放入将来清单

### 两分钟原则
能在 2 分钟内完成的事，立刻做。

### 猴子法则
不背别人的猴子，明确责任边界。如果某件事属于别人，标记为"委托"，不进入自己的行动清单。

### 决策去向
- 自己做：进入项目清单，需指定目标
- 委托：记录委托人，不进入行动清单
- 将来/也许：放入"延迟清单"，不参与日常安排
- 放弃：直接删除或归档

## 三、已转项目（项目-行动两层）
项目不再作为独立导航入口，而是作为事件篮中的“已转项目”Tab 展示。每个项目直接包含行动，不设置任务/子任务层级。

### 项目目标
项目保留一个可选的目标文本字段。独立目标树、目标对象和目标规划页面不纳入当前阶段。

参考"六个高度"简化版：
- 项目目标文本
- 项目（即事件篮中决定自己做的事）
- 行动

创建目标时使用 SMART 原则：具体、可衡量、可达成、相关、有时限。

### 项目字段
- 标题
- 项目目标文本（选填）
- 预计花费时间：项目与其行动的时间预算（单位：小时）。
- 启动日期（选填）：计划开始日期。未到启动日期的行动，默认不出现在行动清单和每日清单中。
- 截止日期（选填）
- 重要程度：二值，重要 / 不重要
- 紧急程度：二值，紧急 / 不紧急
- 优先级：由系统根据重要程度和紧急程度计算，支持手动调整
- 状态：待处理 / 进行中 / 已完成 / 已放弃
- 完成方式：手动标记完成，不自动完成
- 负责人：自己 / 他人（委托）
- 创建时间、备注

### 紧急程度
紧急程度由用户直接选择“紧急”或“不紧急”，当前阶段不根据截止日期自动计算多级紧急程度。

### 优先级计算规则
默认优先级根据重要程度和紧急程度映射为四象限优先级。

四种组合分别对应重要且紧急、重要不紧急、不重要且紧急、不重要不紧急。

用户可以在计算基础上手动调整优先级，系统记录手动调整后的值。

项目使用固定的四象限优先级排序；项目行动支持在项目内手动调整顺序。

### 时间预算联动规则
- 项目直接包含行动，不设置任务层级。
- 项目与行动保留预计时间关联。

### 四象限视图
项目可以按重要程度和紧急程度理解四个象限：
- 重要且紧急
- 重要不紧急
- 不重要紧急
- 不重要不紧急

### 项目拆解
项目直接拆出行动，不设置任务/子任务层级，也不提供思维导图式拆分。

当前阶段项目以事件篮“已转项目”Tab 的项目卡片和行动列表展示。

后续版本再做：
- **OKR 视图**：按目标-关键结果-任务对齐展示
- **甘特图视图**：展示项目/任务的时间安排

### 两分钟原则与猴子法则
- 项目清单中标记预计 2 分钟内可完成的行动，建议立即执行。
- 委托事项保留在事件篮“已委托”Tab，不进入项目列表。

---

## 四、行动清单
近期要做的行动列表，是"下一步行动"的集合。

包含两个子视图：
- **我的行动**：自己执行的行动
- **委托给他人**：委托给他人的行动，记录指派对象、截止日期、提醒

从项目拆解出的行动，先进入行动清单，等待被安排到每日工作清单。行动必须从项目入口创建，不支持独立行动。

### 字段
- 标题
- 所属项目
- 所属项目
- 预计花费时间：用于估算需要几个番茄
- 启动日期：计划开始日期
- 截止日期（选填）
- 是否今日青蛙（系统推荐，可手动调整）
- 状态：未开始 / 进行中 / 已完成

---

## 五、每日工作清单计划
定位：做规划的核心落地执行点。

每天早上从行动清单中挑选今天要做的行动，组成每日工作清单。

### 先吃掉那只青蛙
每天先做最难/最重要的事。系统根据优先级、截止日期临近程度和启动日期是否已到，自动推荐 1-3 个青蛙任务，用户也可以手动调整。

## 六、每日工作清单执行——番茄钟
<!-- 这是一张图片，ocr 内容为：专注时段 25分钟 下一个:5分钟休息 -->
![](https://cdn.nlark.com/yuque/0/2026/png/35384981/1786069773818-a76f2766-2957-4e32-8a46-c6a77689ebcb.png)

每个行动执行时使用番茄钟：25 分钟专注 + 5 分钟休息。

### 番茄钟记录字段
- 关联行动
- 开始时间
- 结束时间
- 状态：完成 / 放弃 / 中断
- 打断类型：内部分心 / 外部干扰 / 紧急事务（可选）
- 打断原因（可选）

**番茄钟在每日 Tab 内启动和显示。** 用户点击今日行动上的"开始番茄"按钮，在当前页面弹出计时面板。

休息时间或者某个阶段会给用户奖励，用户可以自己按照阶段颗粒度设计奖励池。

---

## 七、奖励池
完成番茄或阶段目标后获得积分，积分可用于兑换奖励。

### 积分规则
- 完成 1 个番茄 = 1 积分（可配置）
- 完成一个重要项目 = 额外积分
- 连续打卡 = 额外积分

### 奖励字段
- 奖励名称
- 奖励描述
- 所需积分
- 兑换状态：未兑换 / 已兑换

### 兑换方式
用户累积足够积分后，自己选择兑换奖励池中的奖励。奖励内容由用户自定义，例如：喝一杯奶茶、看一集剧、买一件想要的东西等。

---

## 八、重复任务/习惯
项目支持设置重复规则，系统按规则自动在项目下生成行动，进入行动清单等待用户安排。

### 重复规则
- 每天
- 每周（可指定周几）
- 每月（可指定日期）
- 自定义间隔（如每 3 天）

### 示例
项目：每天散步 30 分钟
重复规则：每天
自动生成行动：散步 30 分钟

用户每天早上从行动清单中挑选该行动，安排到每日工作清单。

---

## 九、时间日志（V1.0 简化版）
记录每日工作情况，找出问题点。

### 记录方式

- 集中精力工作
- 无意义浪费时间
- 真正休息

系统根据记录生成统计图表，帮助用户发现自己的"时间黑洞"。

### 字段
- 日期
- 时间段（如 08:00-09:00）
- 状态：集中精力 / 无意义浪费 / 真正休息
- 备注（可选）

## 十、复盘
支持每日复盘和每周复盘。

支持生成日志和周报。

每周回顾（Weekly Review）：清空收集箱、检查项目、回顾目标、更新清单。

每日三问：今天做了什么？有什么收获？明天最重要的一件事是什么？

统计与反馈：用数据看见自己的改变。周报/月报：完成率、番茄数、时间分布、目标进度。

# 数据模型与数据流

## 实体关系

- 一个事件可以转为一个项目（一对一）
- 一个项目可以直接包含多个行动
- 一个行动可以产生多条番茄记录
- 一个行动可以被安排到具体的日期（每日工作清单）
- 项目与行动之间保留预计时间关联，不设置任务层级

## 核心规则

- 未到启动日期的行动，默认不显示在行动清单和每日清单中。
- 重要程度和紧急程度由用户以二值方式选择。
- 青蛙任务推荐综合考虑优先级、截止日期临近程度和启动日期。

## 数据流

```
事件篮（未处理事件）
    ↓ 标记为"自己做"
已转项目 Tab（已处理项目，带重要/紧急/优先级）
    ↓ 拆解
行动清单（下一步行动）
    ↓ 安排到某日
每日工作清单
    ↓ 执行
番茄记录
```

## 目标层级

```
项目目标文本
    ↓
项目（= 事件篮中决定自己做的事）
    ↓
行动（下一步行动）
    ↓
番茄记录 / 时间日志 / 复盘
```

# 技术选型

## Tauri + React + 本地 SQLite

| **维度** | **说明** |
| --- | --- |
| 适合原因 | 桌面端体验好、离线可用、Rust 后端适合处理定时任务、包体积小 |
| 数据存储 | SQLite（本地）或本地 JSON + 可选云同步 |
| 番茄钟 | Rust 后端做精确计时，前端负责 UI 展示 |
| 优点 | 安全、性能好、可打包成 Windows/Mac/Linux 三端 |
| 缺点 | 移动端不支持，想做手机版要另开一套 |

### 原因：
- 完整方法论涉及项目、行动、时间记录和番茄记录等关系，SQLite 最稳。
- 番茄钟放在 Tauri 的 Rust 后端，计时精准。
- 桌面端更符合"深度时间管理"的使用场景，用户不会边刷手机边番茄。
- 后续可以叠加 WebDAV / 云同步，不需要一开始就做服务器。
