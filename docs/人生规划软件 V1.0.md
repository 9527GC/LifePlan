# 灵感来源

衣柜整理法（GTD）：收集 → 处理 → 组织 → 回顾 → 执行。
四象限法则、先吃掉那只青蛙、两分钟原则、猴子法则、SMART 目标与番茄工作法共同构成本产品的使用方法。

目标分解：目标 → 事件 → 行动。

# 产品定位

LifePlanTodolist 是一款本地优先的桌面时间管理工具。它帮助用户将脑中的事项先收集到事件篮，再依据重要性、紧急性和责任归属做出处理决定，最后通过行动、今日事、番茄钟与复盘形成执行闭环。

V1.0 聚焦个人使用，数据保存在本地，不依赖云端。

# 主界面结构

当前主界面包含四个主要入口；每日复盘从今日事流程进入：

1. **今日事**：每日时间安排、行动执行与当日复盘；作为应用首页。
2. **事件篮**：收集、处理和跟踪事件，包含待处理、进行中、已委托、推迟、已放弃和已完成视图。
3. **番茄钟**：专注计时与专注记录；进行中的专注可切换为独立的置顶悬浮窗口。
4. **奖励池**：积分、奖励和兑换记录。

行动主要由进行中事件承载；今日事还可安排临时行动和重复行动。当前不设置独立的行动管理导航页。

# 核心设计原则

## 先收集，后决策

任何念头、任务、约定或待办事项都可以先记录为事件。收集阶段不要求立即判断优先级，避免打断当前工作。

## 事件直接承载行动

事件是需要推进和完成的事项单元。用户决定“自己做”后，事件进入进行中状态，并在该事件下新增、编辑、完成、删除和排序行动；不再创建额外的中间管理对象。

## 目标驱动

事件可提前编辑目标文本；“去处理”的梳理步骤要求填写目标，用于说明希望获得的结果。已保存的目标等信息会回显。当前不建立独立目标树。

## 极简原则

V1.0 保留事件、行动、今日事、番茄钟、奖励和复盘等核心能力；不引入任务/子任务、角色责任、情境标签或复杂的多维分类体系。

# 功能模块

## 一、事件篮

脑中任何念头、任务、约定都先放入事件篮。记录后再决定是自己处理、委托、推迟还是放弃。

### 事件状态

- **未处理**：仅收集，尚未决定后续处理方式。
- **进行中**：决定自己做，可在事件下管理行动。
- **已委托**：已指定委托对象，并保留跟进行动。
- **推迟**：暂不处理；设置重新处理日期后，在该日期前一个自然日的本地时间 17:00 自动恢复至推迟前状态；未设置日期时仅手动恢复。关闭或休眠错过恢复时间时，在下次启动或激活窗口时补恢复；不允许设置无效日期或恢复时刻已到的日期。
- **已放弃**：保留历史和放弃原因，不再进入执行流程。
- **已完成**：事件及其行动已完成，可保留查看。

### 事件字段

- 标题（必填）
- 目标文本（选填）
- 截止日期（选填）
- 重要程度：重要 / 不重要
- 紧急程度：紧急 / 不紧急
- 优先级：由重要程度和紧急程度计算
- 青蛙标记：事件下未完成行动统一继承
- 完成时间：独立保存，不随后续编辑改变
- 创建时间、状态、委托信息、推迟信息与行动统计

### 事件处理

- **自己做**：先梳理标题、目标、重要程度、紧急程度、截止日期和青蛙标记，再拆解一条或多条行动。进入时回显事件已保存的内容；每次打开重置表单，避免事件之间残留。
- **委托**：记录委托对象和跟进信息；跟进行动完成后，可选择完成或放弃事件。
- **推迟**：设置重新处理日期；已开展行动的事件可推迟后恢复进行中状态。
- **放弃**：记录原因并归档事件；待办行动按规则级联处理。

### 四象限判断

- 重要且紧急：立即处理。
- 重要不紧急：有计划地推进。
- 不重要紧急：优先考虑委托。
- 不重要不紧急：放弃或推迟处理。

### 两分钟原则

在“去处理”第一步可勾选“2分钟小事直接完成”；完成当前步骤的必填校验后，点击“下一步”立即完成事件，不再进入拆解行动。完成后保留快速完成标记和完成日期。

选项后的问号悬停提示：“如果经分析事件2分钟即可完成，无需拆解行动，可勾选此项，点击下一步后将立即完成事件。”提示宽度为 240px，图标和浮层样式与青蛙说明共用。

### 事件卡片日期展示

- 待处理事件：已设置截止日期时，在新增日期旁显示“YYYY-MM-DD 截止”，字号与同一行一致。
- 进行中事件：截止日期在事件卡片的重要、紧急程度旁展示；按本地自然日计算，当天及逾期为红色，剩余 1–4 天为橘色，5 天及以上为灰色。
- 已完成事件：显示“YYYY-MM-DD 完成”；设置了截止日期时同时显示“YYYY-MM-DD 截止”，不再按当前日期标红。
- 未设置截止日期时不展示截止日期。事件下行动卡片不重复展示事件截止日期。
- 历史完成时间优先从最近一次事件完成积分记录恢复，缺少记录时使用原更新时间补齐；补齐后不随事件编辑变化。

## 二、事件内行动管理

进行中事件可以直接包含多条行动，不设置任务或子任务层级。行动可新增、编辑、完成、恢复、删除，并可安排到今日事执行。

### 行动字段

- 标题（必填）
- 描述（选填）
- 预计耗时：未设置、30 分钟、1 小时、1.5 小时或 2 小时
- 开始日期（选填）
- 所属事件截止日期（只读继承，行动不独立设置）
- 重要程度、紧急程度和优先级
- 青蛙标记：未完成事件行动跟随所属事件，完成后保留标签快照
- 状态、完成时间与排序值

行动开始日期晚于所属事件截止日期时仅提醒，仍允许选择和保存；事件延期或取消期限后，提醒按事件最新截止日期计算。

### 青蛙事件与行动继承

- 在“编辑事件”和“去处理”中可设置“标记为青蛙事件”，旁边提供青蛙法则问号说明。
- 事件标签是其未完成行动的唯一来源：新增、拆解、委托生成和恢复的行动均继承事件标记，不支持单独覆盖。
- 修改事件标签只同步其未完成行动；已完成行动保留完成时标签，恢复为未完成时重新继承。
- 事件篮进行中、已完成事件，以及今日事按事件查看时，青蛙标签仅显示在事件卡片或事件分组标题，不在子行动卡片重复显示。今日事平铺列表和行动详情仍可展示行动青蛙标签。
- 今日事行动详情中，事件行动的青蛙设置显示“青蛙事件”；修改前确认将同步所属事件及全部未完成行动。已完成行动、已完成或推迟事件的行动在该入口不可修改。
- 事件行动编辑框左下角显示不可单独修改的继承状态；重复行动和临时行动保留独立设置，其新增、编辑弹框的青蛙设置与操作按钮同处底栏左侧。
- 旧库升级时，存在未完成青蛙行动的事件提升为青蛙事件，并统一其未完成行动标签；已完成行动和独立行动保留原值。迁移只执行一次。

### 开始日期联动调整

事件篮编辑行动与今日事安排行动中的“调整开始日期”共用规则和预览：

- 默认不勾选“同时调整该事件下的后续未完成行动”，不勾选时仅改当前行动。
- 当前行动原本有开始日期才支持联动；无原日期时，无论设置还是清空都只影响当前行动。
- 勾选后按当前行动变更的自然日天数统一提前或后延，保留日期间隔；后续未设置日期的行动跳过并提示数量。
- 勾选后清空开始日期，会一并清空后续未完成行动的日期；已完成行动和其他事件的行动不参与。
- “后续”使用打开弹框时的排序快照，搜索不缩小范围。事件篮按完整事件顺序，今日事按当前平铺或事件视图的完整事件顺序确定。
- 显示原日期与新日期预览、实际变更数量、早于今日和超过事件截止日期的提醒；提醒不阻止保存。
- 批量保存使用更新时间快照校验和事务，冲突时整批失败；事件篮同时编辑标题、耗时等字段时与日期调整一并保存，避免部分成功。

### 行动完成

- 完成行动会记录完成时间。
- 已完成行动可恢复为待办。
- 进行中事件满足完成条件后，用户可完成事件。
- 已完成或推迟事件下的行动不允许编辑；已完成事件下的行动不允许删除或重新排序。

### 事件内行动排序

行动显示顺序由已保存的 `sort_order` 和 `start_date` 共同决定：

1. 先按 `sort_order` 升序建立稳定基础顺序；缺少有效排序值时按创建时间和 ID 兜底。
2. 未设置开始日期的行动固定在其原有位置，可以夹在有日期行动之间。
3. 有开始日期的行动按开始日期升序填入其余位置；同一天的行动沿用手动排序。
4. 清空开始日期只清空日期字段，不会把行动自动移到末尾，也不会重排其他未修改行动。
5. 新增开始日期或将日期修改为其他日期后，该行动参与日期排序。
6. 仅支持在相同开始日期的行动之间拖拽排序；两个都未设置开始日期的行动也属于同一可排序组，不支持跨日期拖拽。

示例：`9 月 28 日 → 9 月 29 日 → 9 月 30 日` 三条行动中，将中间行动的开始日期清空后，顺序保持为 `9 月 28 日 → 未设置日期 → 9 月 30 日`。

## 三、今日事与日程

今日事用于把准备执行的行动安排到具体日期和时间段。事件行动选择器展示未完成且所属事件未推迟的行动，不按开始日期隐藏未来行动；未设置开始日期的行动也可安排。

### 日程能力

- 每日时间段和计划模板。
- 将行动安排到指定日期和时间段。
- 支持查看已安排日期，并在日程中调整行动。
- 同一行动可在需要时安排到多个时间段；删除排程不删除行动。
- 可创建临时行动，用于不属于特定事件的当日事项，并设置重要程度和紧急程度。
- 事件行动支持搜索、平铺 / 按事件视图切换，并保留视图偏好；同 P 级青蛙优先，平铺视图仍先按开始日期排序。完整入口见《[事件与行动排序规则](./事件与行动排序规则.md)》。
- 重复行动支持规则自动安排或手动创建实例，详见“重复行动与习惯”。

### 时间段复盘与每日复盘

- 在每个已安排行动的时间段中记录实际情况、是否达到预期、是否专注和主要偏差原因。
- 当当天所有已安排行动的时间段均完成复盘后，可进入每日复盘，查看行动完成度、四象限安排、执行轨迹和偏差汇总。
- 每日复盘支持约 700ms 防抖自动保存 Markdown 思考内容，浮层显示保存中、已保存时间或失败状态，并依据时间段结果自动判断当天是“顺利”“有偏差”还是“比较混乱”。
- 每日复盘引导先清空待处理事件篮，再初始化次日重复行动并进入次日今日事安排其余计划和青蛙行动；初始化失败则不跳转；近 7 天重复出现至少 3 天的偏差原因会以本地规则建议提示。

详见《[每日复盘功能说明](./daily-review-development.md)》。

## 四、番茄钟

番茄钟用于专注执行行动，并记录专注时长。用户可从今日事行动详情进入番茄钟，也可在番茄钟页面选择关联今日行动或进行自由专注。

- 可按预计时长开始专注，系统按 25 分钟工作、5 分钟休息的轮次展示进度；支持立即完成或记录中断原因。
- 专注进行中可一键切换为独立、置顶的悬浮番茄钟窗口。悬浮窗口会显示当前行动、剩余时间和轮次，位置与尺寸单独记忆；关闭悬浮窗口会回到主窗口。
- 完成专注后会记录专注历史并发放积分，可直接开启下一次专注；若关联了行动，也可直接进入每日复盘。
---

### 今日专注

- 番茄钟展示本地当天专注分钟数、完成次数、中断次数、专注 / 休息时间轴及中断原因。
- 专注时长按固定 25 分钟工作、5 分钟休息规则重建，裁剪到当日、实际结束时间和计划结束时间；不包含休息，不补算提前结束后的时间，跨日记录只计当日部分。
- 番茄钟记录按开始时间倒序；每日复盘共用组件并按正序展示，宽窗口与执行轨迹等高并排，窄窗口纵向排列，溢出记录可展开和收起。

## 五、奖励池

完成行动、番茄或其他满足条件的行为可以获得积分；积分可兑换用户自定义奖励。

### 积分流水

- 点击奖励池或番茄钟积分余额打开流水；番茄钟弹框还可前往奖励池兑换。
- 按当前本地空间隔离，按发生时间及编号倒序，每页 20 条；可筛选专注奖励、事件完成、奖励兑换，全部类型还包含奖励撤回和历史余额调整。
- 新流水与余额变更处于同一事务，保存发生时的名称快照；事件奖励撤回记录实际扣除值，余额不低于零。
- schema 升级到 23，首次建表导入可恢复历史汇总，以“历史余额调整”对齐已有余额，不重新发放积分；历史汇总不是完整逐笔历史。

### 奖励字段

- 奖励名称
- 奖励描述
- 所需积分
- 模板状态：活跃 / 归档；兑换记录与奖励模板独立管理

## 六、重复行动与习惯

重复行动独立于事件行动管理，模板用于生成可执行实例。支持搜索、新增、编辑、上移 / 下移排序和删除，也可手动从模板创建实例；删除模板不会删除已生成实例。

### 重复规则与字段

- 标题必填；单次耗时可选 30 分钟、1 小时、1.5 小时或 2 小时。
- 开始时间采用半小时刻度，支持多选，默认 08:30；可独立设置青蛙标记。实例创建时复制模板标记，修改模板只影响以后生成的实例；修改某个实例不回写模板或其他实例。
- 界面支持每天、每周多选星期、每月多选 1–31 日。每天、每周可设置 1–4 天或周的重复间隔及开始日期，以开始日期为锚点；每月不提供间隔选项。某月不存在选定日期时不会顺延到月底。
- 新建或编辑保存时启用自动安排；模板及生成实例默认不重要、不紧急，优先级为 P4。
- 旧模板默认不自动安排，显示“待设置重复规则”，需编辑保存确认后启用。兼容数据中的工作日规则仅指周一至周五，编辑时转为每周选择，不识别法定节假日或调休。

### 触发与排程规则

1. 主应用启动时初始化本地当天；悬浮番茄钟窗口不触发。每日复盘点击“去安排明日计划”时，先初始化当前复盘日期的次日，再跳转。
2. 先按日程模板初始化目标日期时间段，再按模板排序值和 ID 处理匹配该日期的重复行动。
3. 从包含所设开始时间的整个时间段开始，不拆分时间段。因此开始时间落在段内时，实际排程可能从该段起点开始；没有覆盖开始时间的段，或起始段已有行动，则跳过。
4. 顺序占用连续空白时间段，累计达到单次耗时后停止；遇已有行动或时间断档即停止，不覆盖、不跨断档，也不跳到后面补排。只要至少选到一段，即使时长不足也会生成实例；多个段共享同一个实例。
5. 每个本地空间、每个日期只初始化一次，启动和复盘触发共享该限制。即使首次没有可排时间段或旧模板未确认，也会记录初始化；随后新增、修改模板或腾出空档不会自动回填该日期。仍可手动创建和安排实例。

示例：设置“散步 30 分钟”，每天 08:30 开始。当目标日期存在覆盖 08:30 的空白时间段且尚未初始化时，系统生成一个实例并绑定该段；如果起始段已占用，则不自动改到其他时段。

当前没有跨午夜定时自动排程或持续补排机制。

## 七、复盘与统计

### 每日复盘

聚焦“计划了什么、实际做了什么、是否达到预期”，可辅助回答：今天做了什么、有什么收获、明天最重要的一件事是什么。

### 每周回顾（使用建议）

当前没有独立每周复盘页面。可手动按待处理事件逐条清理，选择自己做、委托、推迟、放弃或删除；同时检查行动执行和统计数据。

### 统计与反馈

当前提供本地匿名操作日志，用于记录核心功能的使用事件，不记录事件、行动或复盘等业务文本。连续点击左上角 LifePlan Logo 三次可导出本地日志。

# 数据模型与数据流

## 实体关系

- 一个事件可以包含多条行动。
- 一个行动可以产生多条番茄记录。
- 一个行动可以被安排到具体日期的今日事或日程时间段。
- 一个事件可关联委托信息、推迟信息和行动完成统计。
- 重复行动与事件行动分别管理。

## 核心规则

- 事件优先级仅根据重要程度和紧急程度计算。
- 行动优先级仅根据重要程度和紧急程度计算。
- 行动开始日期和事件截止日期均为选填；行动开始日期超过事件截止日期仅提醒，不阻止保存。
- 未设置开始日期不代表排在行动列表末尾，详见“事件内行动排序”。
- 不提供自动青蛙推荐算法；用户设置事件青蛙标记，事件下未完成行动统一继承。重复行动模板、实例和临时行动按各自规则设置。
- 青蛙排序不改变 P 级，只在既有排序条件相同的同 P 级内优先展示；日期、状态置顶和手动排序规则见排序说明。

## 数据流

```text
事件篮（未处理）
    ↓ 自己做
进行中事件（目标、四象限信息、行动）
    ↓ 拆解与安排
事件内行动
    ↓ 安排到某日
今日事 / 日程
    ↓ 执行
番茄记录与每日复盘
```

## 目标层级

```text
事件目标（选填）
    ↓
进行中事件
    ↓
事件内行动
    ↓
番茄记录 / 今日事复盘
```

# 技术选型

## Tauri + React + 本地 SQLite

| 维度 | 说明 |
| --- | --- |
| 桌面框架 | Tauri，提供原生桌面窗口与 Rust 后端能力。 |
| 前端 | React、TypeScript、Vite 与 Ant Design。 |
| 数据存储 | SQLite，本地优先；后续可扩展同步能力。 |
| 计时 | Rust 后端维护番茄钟状态，前端展示交互界面。 |

选择本地桌面架构，是为了提供离线可用、性能稳定、易于备份的个人时间管理体验。

# V1.0 版本边界

## 当前包含

- 事件篮及其六种状态视图。
- 事件直接管理行动的两层结构。
- 事件和行动的四象限优先级。
- 今日事、每日时间段、计划模板和行动安排。
- 番茄钟与专注记录。
- 奖励池、积分与奖励兑换。
- 重复行动模板、每日 / 每周 / 每月规则和首次自动排程。
- 每日复盘、时间段复盘和本地操作日志导出。
- 本地空间隔离和本地备份能力。

## 当前不包含

- 独立目标树。
- 独立行动管理导航页。
- 额外中间层级、任务/子任务和思维导图。
- 独立四象限决策台。
- 自动青蛙推荐算法。
- 时间日志模块与按小时分类记录。
- 预置示例数据。

## 后续可扩展

- OKR 视图
- 甘特图视图
- 云同步
- 移动端
- 周报、月报与更完整的统计视图
