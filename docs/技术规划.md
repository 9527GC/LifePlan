# LifePlanTodolist V1.0 技术规划

## Context

用户希望基于《小强升职记》的时间管理理念，构建一款桌面端时间管理工具。项目目录 `E:\项目\LifePlanTodolist` 目前仅包含产品文档 `docs/人生规划软件 V1.0.md`，没有任何代码骨架。本规划的目标是从零搭建一个可运行的 Tauri + React + SQLite 桌面应用，并完成 V1.0 功能边界。

## Goals

1. 实现 V1.0 完整功能闭环：事件篮 → 项目清单 → 行动清单 → 每日清单 → 番茄钟 → 复盘。
2. 建立清晰的数据模型，支持项目/行动两层结构和项目时间预算联动；重要程度与紧急程度采用二值模型。
3. 保证番茄钟计时精准、数据本地可靠、支持自动备份。
4. 为后续 OKR/甘特图、云同步、移动端扩展预留结构。

## Technical Stack

### 后端
- **Tauri v2** + **Rust**
- **rusqlite** + 自定义 Tauri Commands（而非 `tauri-plugin-sql`）
  - 理由：需要 Rust 层处理番茄钟精确计时、父子时间预算校验、青蛙推荐算法、自动备份等复杂逻辑，自定义 commands 更灵活。
- 数据库文件本地存储，路径由 Rust 层统一管理。

### 前端
- **React 18** + **TypeScript**
- **Vite**（Tauri 默认集成）
- **Tailwind CSS** + **shadcn/ui**
  - 理由：可定制性强、按需安装、适合桌面端。
- **Zustand** 状态管理
- **React Router** 路由（Tab 内页面切换）
- **date-fns** 日期处理

### 数据
- **SQLite** 本地文件
- 表结构采用自增 ID，核心实体使用 `created_at`/`updated_at` 时间戳。
- 启动时自动执行数据库迁移（migrations），支持版本升级。

## 核心算法

### 1. 二值重要程度与紧急程度
`importance` 和 `urgency` 均为 0/1，由用户直接选择重要/不重要、紧急/不紧急，不根据截止日期自动计算多级值。

### 2. 优先级计算
- 默认按四种重要/紧急组合映射为 1-4 的四象限优先级。

### 3. 项目-行动时间预算
- 项目直接包含行动，不设置任务层级。
- 项目预计时间与行动预计时间保持关联。

### 4. 青蛙任务推荐
从满足以下条件的行动中综合评分：
- 启动日期 ≤ 今天（或已过期）
- 状态为未开始
- 已安排到今日或优先级高

评分公式：
```
score = priority × 0.5
      + (30 - min(30, days_to_deadline)) × 0.3
      + (is_in_today_plan ? 20 : 0)
```
取 Top 3 作为推荐青蛙，用户可手动调整。

### 5. 行动清单可用性
- 启动日期 > 今天：不显示在行动清单和每日清单中
- 启动日期 ≤ 今天：正常显示
- 已完成的行动：默认隐藏，可在过滤中查看

## Implementation Phases

### Phase 1: 项目骨架 + 数据库（1-2 天）
1. 使用 `npm create tauri-app@latest` 初始化 Tauri v2 + React + TypeScript + Vite 项目。
2. 配置 Tailwind CSS，初始化 shadcn/ui。
3. 在 Rust 中集成 `rusqlite`，创建数据库连接和迁移机制。
4. 创建 `events`、`projects` 和 `actions` 表及对应的 CRUD Commands。
5. 创建事件篮和行动页面骨架。

### Phase 2: 事件篮 + 项目行动闭环（2-3 天）
1. 实现事件篮列表页，支持新增/编辑/删除事件。
2. 示例数据不作为当前阶段必需项。
3. 事件转项目流程。
4. 项目直接管理行动。

### Phase 3: 项目卡片与行动管理（2-3 天）
1. 项目列表视图，按优先级排序。
2. 事件篮“已转项目”Tab。
3. 项目行动列表和排序。
4. 二值重要/紧急和四象限优先级。
5. 项目状态管理。

### Phase 4: 项目拆解 + 行动清单（2-3 天）
1. 项目详情区域支持添加和管理行动。
2. 不实现任务/子任务和思维导图。
3. 项目-行动预计时间关联。
4. 行动清单列表。

### Phase 5: 每日清单 + 青蛙推荐（2 天）
1. 从行动清单挑选行动到每日清单。
2. 青蛙任务推荐算法。
3. 手动标记/取消青蛙。

### Phase 6: 番茄钟（3 天）
1. Rust 层精确计时器。
2. 每日 Tab 内番茄钟 UI。
3. 完成/放弃/中断记录。
4. 打断类型和原因记录。
5. 番茄记录与积分系统联动。

### Phase 7: 奖励池 + 时间日志 + 复盘（3 天）
1. 奖励池 CRUD 和积分兑换。
2. 时间日志每小时手动记录。
3. 每日三问模板和每日复盘。
4. 每周回顾向导。
5. 简单统计报表。

### Phase 8: 自动备份 +  polish（2 天）
1. Rust 层定时自动备份 SQLite 文件。
2. 设置页面。
3. 首次使用引导流程优化。
4. 整体 UI 调优。

## Key Technical Decisions

### 为什么用 rusqlite 而不是 tauri-plugin-sql？
- 需要 Rust 层处理番茄钟计时、父子预算校验、青蛙推荐、自动备份等逻辑。
- 自定义 commands 更灵活，便于后期扩展。
- 数据一致性在 Rust 层更容易保证。

### 为什么用 shadcn/ui？
- 基于 Tailwind，可高度定制桌面端界面。
- 按需安装组件，避免引入大量无用代码。
- 与 React + TypeScript 生态无缝集成。

### 为什么用 Zustand 而不是 Redux？
- 状态管理需求中等，Zustand 足够轻量。
- 减少样板代码，加快开发速度。

## Risks & Mitigations

| 风险 | 缓解 |
|------|------|
| 番茄钟后台计时不准 | 由 Rust 层处理 timer，使用系统时间；Tauri 事件通知前端刷新 UI。 |
| 项目拆解模型保持简单 | V1.0 采用项目-行动两层卡片/列表，不引入任务树或思维导图。 |
| 时间预算联动校验复杂 | 核心校验在 Rust 层，前端只展示警告；允许用户预留缓冲。 |
| 自动备份目录权限问题 | 默认备份到应用数据目录；用户可修改，修改失败时友好提示。 |

## Verification Plan

每个 Phase 完成后执行：
1. `npm run tauri dev` 能正常启动。
2. 数据库文件生成且无错误。
3. 手动走一遍该 Phase 的核心功能路径。
4. 检查数据库表数据是否符合预期。

最终 V1.0 验证：
1. 新用户首次打开进入事件篮；示例数据不作为当前阶段验收项。
2. 添加一个事件 → 转为项目 → 设置目标/重要/紧急/优先级。
3. 拆解项目 → 生成行动 → 安排到今日。
4. 开始番茄钟 → 完成 → 查看积分增加。
5. 填写时间日志 → 查看统计报表。
6. 检查备份目录生成了数据库备份文件。
